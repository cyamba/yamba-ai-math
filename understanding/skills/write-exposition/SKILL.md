# Write exposition

## Plan before drafting

1. **Brief**: audience, prerequisites, goal (what the reader can do afterwards), length, format
   (Markdown, LaTeX, self-contained HTML) and venue.
2. **Inventory**: the results to cover, each with status and source; the definitions; the
   examples (forge-examples); the figures (visualize-math).
3. **Style**: choose from [styles.md](../../references/styles.md). The default for teaching is
   example first, then statement, idea, proof and applications.
4. **Outline** with a path through the [levels](../../references/levels.md) and a figure plan
   with one figure per key idea.

## Draft

- **Each section**: motivation in one paragraph, an example, the statement, the idea, the steps,
  the consequences, one check question.
- **Exercises in four tiers**: check (definitions), routine (direct use), explore (compute and
  conjecture, marked exploratory), challenge (needs an idea). Put hints and solutions apart.
- **Notation**: consistent with the source; a notation table for longer pieces.
- **Citations**: primary sources next to claims. A source that a research file relies on also
  needs an entry in `references/reading-list.md` (repository root).

## Textbook and course mode

Organize chapters as a spiral that returns to earlier objects at higher levels. Keep a running
example across chapters. End each chapter with a summary, a list of ideas the reader can now use,
and exercises.

## Checks

Run the [quality checklist](../../references/quality-checklist.md). Apply the no-em-dash rule to
all prose, titles, captions and alt text. Do not reproduce third-party text beyond short
quotations; paraphrase and cite.

## Publication

A draft is not a publication. Posting, submitting or releasing material needs the operator's
separate authorization; an article from a research project follows that project's own paper or
publication instructions.
