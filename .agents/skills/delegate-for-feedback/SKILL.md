# Delegate a question and preserve its return

Choose a subproblem whose answer would change the next decision: a narrow lemma,
invariant, inverse audit, counterexample or source comparison. Explain the
connection to the complete KR1 bijection without assigning the operator the whole
open problem. Match the scope to their chosen time and tools; do not invent a
commitment or assume that external work has occurred.

Create or update a packet in
[feedback.md](../../../research/rogers-ramanujan/feedback.md):

- Stable ID, project, kind, PENDING status, proposed owner (the operator),
  and source/result links (mark the result as not yet returned).
- Exact objects, assumptions and question; known rules and failed witnesses.
- Why the answer matters, smallest useful falsifier, requested artifact and a
  suggested stopping point. A conditional result or counterexample is valuable.
- A return slot: claim/status, argument or exact object, source inspection depth,
  reproducible code/commands if used, resource exposure, and remaining uncertainty.

A packet is a durable mental note, not a claim of delivery or acceptance. Present
it locally; send externally only when requested, using yamba-post if appropriate.
A pending optional question need not block other authorized work.

When feedback arrives, retain the original packet and return verbatim or by a
linked artifact with provenance. Check assumptions, reproduce decisive computations
within the current budget, and record the effect on the next lemma. Mark RECEIVED
before review, then record the review verdict separately. Human or model agreement
alone is not proof; substantive accepted claims need the applicable semantic audit.
