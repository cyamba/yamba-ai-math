# Reflect on improvements before the next run

Use when preparing to restart research or when the operator requests pre-run tweaks.
Read root CLAUDE.md, the latest regroup/result, relevant review findings, pending
feedback and the proposed run contract. Distinguish feedback actually received
from questions merely queued. Keep this reflection short and count it within the
declared investigation budget; it does not launch a new attempt or reset a ledger.

Choose one or two small improvements supported by an observed difficulty. Examples
include reserving criticism until the intended proof is ready, asking for an
intrinsic inverse before coding, or tracing a collision's lost statistic before
another sweep. These are proposals to assess, not demonstrated improvements.
Keeping the existing workflow is a valid outcome.

For each proposed tweak, record:

- Evidence: exact prior event, proof gap or receipt; distinguish observation from
  the hypothesized cause.
- Change: what will differ next time, which decision it should improve, and why.
- Cost and risk: time, computation, coordination or review displaced; ensure the
  next contract still covers discovery, verification, criticism and handoff.
- Check: an observable outcome that would support or challenge the tweak, and a
  condition for revising or dropping it. Scientific success remains the original
  KR1 objective, not this process measure.
- State: proposed, applied or deferred, with a reason. Apply authorized reversible
  local preparation changes; do not imply that writing a proposal executed it.

Save one concise dated pre-run note in the next attempt's research folder, or the
current handoff if no new attempt is declared. Include the unchanged objective,
decisive next lemma, chosen tweaks and one concrete first action with a stop
condition. Preserve prior proposals and failures. Freeze the candidate and its
claims before verification; previously inspected cases remain discovery exposure.

Preserve universal proof standards, separate semantic criticism, attribution and
novelty limits, plus the active resource and local-only/no-push safeguards. A tweak
adds no agents, mechanisms, rounds or budget. RR003 is closed. Route a mathematical
change of approach through [pivot](../pivot/SKILL.md), and a useful human question
through [delegate-for-feedback](../delegate-for-feedback/SKILL.md). Broader harness
changes require separate evaluation under the repository's meta protocol. Label
workflow benefits unvalidated until evaluated; one run establishes no general
increase in discovery success.
